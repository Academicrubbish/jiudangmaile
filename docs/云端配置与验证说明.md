## 2. 云空间与账号

1. 将 `uniCloud-aliyun` 关联到你用于测试的阿里云服务空间。
2. 核实 `uni_modules/uni-config-center/uniCloud/cloudfunctions/common/uni-config-center/uni-id/config.json` 内的微信登录配置：微信 AppID、AppSecret 以及有效的 tokenSecret 等。原模板配置文件保留原样，本次没有改写密钥。
3. 上传账号模块 `uni-id-co` 及其依赖公共模块，包括 `uni-id-common`、`uni-config-center` 等，按 HBuilderX 提示安装／上传依赖。
4. 从 uni-id 模块初始化其实际需要的账号集合；不要导入初始演示用户、权限测试数据或默认管理员数据。

客户端只通过微信登录建立真实账号；H5 构建可以检查代码，但当前版本未接入网页账号登录。不提供使用任意用户编号冒充登录的开发后门。

官方核对入口：

- [uni-id 云对象](https://doc.dcloud.net.cn/uniCloud/uni-id/cloud-object.html)
- [uni-id-common](https://doc.dcloud.net.cn/uniCloud/uni-id/cloud-common.html)

## 3. 上传业务数据库和云函数

业务集合：`jdml-users`、`jdml-events`、`jdml-days`、`jdml-invites`、`jdml-requests`、`jdml-ai-usage`、`jdml-ai-audit`、`jdml-notices`。

上传 `uniCloud-aliyun/database/jdml-*.schema.json` 和事件／用户任务索引。八个业务集合均禁止客户端直接读写，由云函数管理；不要为了排错将权限改成公开。

上传并部署 `uniCloud-aliyun/cloudfunctions/jdml-api`，同时上传它依赖的 `uni-id-common` 与 `jdml-core` 公共模块。随机任务还需部署 `jdml-worker` 及其定时触发器，详见 [AI 与随机提醒接入](AI与随机提醒接入.md)。该云函数不用配置 HTTP URL 化，前端通过 `uniCloud.callFunction` 调用。

事务使用阿里云支持的 `startTransaction`，通过确定的文档 ID 读写，并主动 commit／rollback。存在写冲突时有限重试，同一次客户端请求使用相同操作编号恢复结果。

参考：[uniCloud 云函数数据库事务](https://doc.dcloud.net.cn/uniCloud/cf-database?id=start-transaction)。本地测试替身不能证明云空间的配置正确，仍需真实部署验证。

## 4. 建议验证顺序

1. 用微信测试账号 A 进入：开场、默认 20 元与奶茶设置，获得第一件 10 元小事。
2. 点击假装消费，只出现小票；复制金额后返回，转存统计仍为零。
3. 确认实际转存 12 元，再主动创建一件小事，金额最多为剩余 8 元；重复确认不重复记入。
4. 回顾事件与物品，撤销一笔误记，再重新填写实际金额。
5. 跳过或处理当前事件后，创建请客卡，分享给账号 B。
6. B 打开只预览，点接受后才占名额。A、B 都能看同一事件，但只有 A 可以确认自己的转存。
7. 再用账号 C 打开相同邀请，不能再次领取。A 也不能领取自己发出的邀请。
8. 验证撤销、24 小时过期、断网重试、重新进入、昵称头像和跨天记录。

确认是自报记录，无需实际转账即可用测试账号检查流程。若做真实转存，资金操作在你自己的官方客户端完成。
