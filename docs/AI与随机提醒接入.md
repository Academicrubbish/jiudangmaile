## 模型选择与私密配置

默认模型为 **glm-5.2**，采用智谱标准 Chat Completions 接口：

`https://open.bigmodel.cn/api/paas/v4/chat/completions`

选择旗舰模型承担短篇中文创作和独立复核，不用轻量模型自动替换。输出仅为一件短场景，关闭深度思考；模型标识保留为可配置项。这个选择尚需结合真实故事样本验证，不能把模型级别等同于成品质量保证。

依据：[GLM-5.2 官方模型说明](https://docs.bigmodel.cn/cn/guide/models/text/glm-5.2)、[智谱对话补全接口](https://docs.bigmodel.cn/api-reference/模型-api/对话补全)、[思考模式参数](https://docs.bigmodel.cn/cn/guide/capabilities/thinking-mode)。

你提供的 Key 已保存于：

`uniCloud-aliyun/cloudfunctions/common/jdml-core/config.local.json`

文件已加入 Git 忽略，权限为当前用户可读写；没有把 Key 写进客户端或示例配置。`config.example.json` 是不含密钥的配置模板。也支持在云端通过 `JDML_ZHIPU_API_KEY` 环境变量覆盖密钥。

上传公共模块时，需要在服务端保留有效配置；仅从 Git 拉取工程不会获得本地私密配置。不要把该文件移到 static、前端 services 或公开托管目录。

## 生成规则

1. 云端先确定用户人设、物品、金额、场景类型、时段和变化种子。模型不接收昵称、头像、用户编号、邀请凭证或转存记录。
2. 模型只返回标题、正文、按钮、原样金额与主题标识。输出限定 JSON、长度、金额一致、物品一致；拦截明显的倒霉、疾病、冲突、道德施压、到账谎称和链接。
3. 通过格式检查后，再发起独立语义复核。复核失败、超时或不可用均不发布该候选；不使用生成结果自行声称的“已审核”。
4. 和最近七天、最多十件故事比较文本及主题，避免重复。
5. 成功或兜底都写入事件快照。已展示结果不被迟到响应改写；请客事件和公开邀请理由同步保存。

首次与主动场景的 AI 等待预算默认 **8 秒**，定时预生成默认 **25 秒**，不含数据库与网络接入的其他耗时。这一轮根据用户优先内容质量的要求，将原计划的约三秒目标调整为八秒；前端等待时保留明确反馈。后续根据真实耗时再调，不使用更弱模型静默替代。

默认每用户每天最多六次模型请求，包含独立复核和失败重试；单次生成最多重试一次。达到调用边界会使用预审文案。不是用户付费或存钱额度，也不会阻止回顾、确认或领取请客。

生成记录保存模式、提示词版本、模型名称、耗时、主题和正文哈希。失败审计仅保存有限原因代码，不存请求头、Key 或供应商原始响应。完整提示词在公共模块的 `prompts.js`。

## 随机事件

- 每天按北京时间保存一次计划，低日参考金额最多一件，其余最多两件。
- 首次现场事件算进当天名额；修改设置不清零已发生数量。
- 95% 的候选时间取自 08:00–21:00，5% 取自 07:00–08:00 或 21:00–22:00。受剩余时间和至少三小时间隔限制时少安排，不为满足比例强行补发。
- 未来事件提前十五分钟准备，在到期前不展示、不占当前可执行额度；到期重新检查剩余额度、人设和未处理事件，再决定是否展示。
- 主动消费会替换一件未来事件；跳过不自动新增替补。
- 22:00–07:00 不自动生成或提醒，夜间主动玩法仍可使用。
- 三个自然日未打开后暂停新任务。定时器自身不会刷新用户活跃时间。
- 应用前台每九十秒更新一次在线状态，避免人在使用时再收到外部提醒。

准备时间与消费时段分开，模型按事件的到期时段写作。云端任务重跑不会创建第二份同一计划事件。

## 微信订阅提醒

发送代码已经完成，目前私密配置中 `subscription.enabled` 为 false，原因是尚未提供适用模板 ID 和字段。没有配置时不会弹订阅窗口，也不会声称已开启提醒。

需补齐：

- 实际获准的 `templateId`。
- 模板字段 `data`，填写对应字段的固定文案；代码不允许 AI 自行填入任意推送正文。
- `miniprogramState`：开发验证用 developer，体验版用 trial，正式版用 formal。
- uni-open-bridge 所需的微信应用凭据，以及对应 DCloud AppID 的微信 openid 记录。密钥放在该模块的私密配置中。

取得字段后按真实模板填写；示例字段名不能直接当成已获准模板。`data` 的配置格式是“字段名 → 字符串”，适配器会转换成微信需要的 value 对象。

用户必须点击“提醒我一次”触发微信授权窗口，拒绝照常玩。服务器保存的是客户端报告的提醒意愿，不将其当成微信许可的独立证明；最终以微信接口结果为准。

发送前检查时段、用户活跃、事件有效、是否暂停、是否有提醒意愿与当天是否已尝试。每天最多一次；返回 accepted 只表示接口受理，不等于已送达或已阅读。状态未知不盲目重发，工作函数崩溃遗留的 sending 记录也不重复接管发送。

暂停会阻止尚未发出的后续请求；已经向微信发起的请求不能由本程序撤回。

凭据接口依据：[uni-open-bridge 官方说明](https://doc.dcloud.net.cn/uniCloud/uni-open-bridge)。微信官方订阅文档在本次抓取中不可读，发送接口与配置仍须结合账号后台和实际返回值验证，代码不承诺模板资格或长期订阅能力。

## 验证时观察什么

先验证开场和主动事件：在云数据库查看事件的 generation.mode 是否为 ai，模型是否为 glm-5.2，正文和金额是否匹配。若使用了兜底，可查看 jdml-ai-audit 中的原因代码；HTTP 类错误需要在智谱控制台核对权限与账号状态，不能靠反复刷新制造新请求。

然后观察 nextJobAt 和当天 plan：预先生成的事件应为 planned，到期后才为 offered；自己主动创建事件后，相应未来计划应为 replaced，预生成事件为 cancelled。

最后用获准模板验证订阅请求和 jdml-notices 状态。真实模型的二百条内容评测、实际延迟、云数据库并发和真机体验尚待验证，本轮本地测试不能代替这些结果。
